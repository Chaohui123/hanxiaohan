# ONZO 项目现行工程约束

> 2026-11-04 按真实代码、生产配置和现行 SOP 重写。本文件取代早期 Phase 1 的“禁 Python/Redis、仅 SQLite、仅 API、旧模型路由”等约束；原文已备份，不得恢复为当前规则。

## 一、规则入口与适用范围

1. 先读 [AGENTS.md](../AGENTS.md)、[当前工作状态](../docs/current-pipeline.md) 第九节，并按任务检索知识库；生产运维同时读 [运维手册](../docs/operations-manual.md)。
2. 当前规则以 `AGENTS.md` 和现行 SOP 为准。`temp/` 下的调研、旧交接、实验记录和第三方参考文档不是工程约束或生产操作授权。
3. 历史资料必须标注日期与“历史/当时/设计目标”；历史待办不得直接变成当前任务。

## 二、现行技术栈

- 主业务使用 TypeScript、Node.js 22+、pnpm monorepo、Express；前端为 React/Vite。
- 生产使用 PostgreSQL 16 + pgvector 和 Redis 7；RAG 当前为 `vector(1024)`。standalone 的 SQLite 仅限本地/降级场景。
- 使用 Docker Compose、Caddy 和 api-services 内建 scheduler；n8n 是可选项，不是定时任务的唯一入口。
- Python 用于现有图像、视频、配音、转录及部分运营脚本，不再一概禁止；不得无理由替换主业务技术栈。
- LangGraph 仅沿用仓库已有的受控工作流，不引入未经审计的自主循环 Agent 框架；不引入 Qdrant 替代现有 pgvector。
- 1688/浏览器交互按现有工具与授权流程执行，不再沿用“一期只允许 API”的过期限制。

## 三、生产安全与模型边界

1. Ozon 商品、价格、库存的写入及生产回读终审只能由 Kimi 主 Agent 执行。GPT、Gemini、Opus 和零上下文子代理只做分析/生成，不直接操作生产数据。
2. 浏览器操作由主 Agent 直跑；不得让子代理串用浏览器会话。任何生产写入前先备份，写后按真实字段回读，不能仅凭 `updated=true` 验收。
3. `PROMO_AUTO_DECISION=false`；不得擅自开启自动调价、扩大 Direct 投放或修改预算。Direct marketplace 设置按现行后台流程处理，Reports API 只读。
4. Ozon import 是全量替换。增量补属性后必须回写建品脚本；重提前对比线上属性、图片、视频和富内容。
5. 兼容件文案禁止 `оригинал`、`аналог` 和他人品牌词；OE 编号、适配关系和商品参数必须有证据，不得由模型推断成事实。
6. 密钥、令牌、客户隐私和生产配置不得写入文档、日志或发送给外部模型。文档脱敏不等于实际凭据已轮换。

## 四、工程实施要求

- 先确认仓库已有依赖、配置入口和代码风格，不因常见而新增库；复用现有 Ozon API 限流、错误处理和数据库适配层。
- 数据库操作使用现有参数化适配器与事务；池化 PostgreSQL 使用单连接事务，不把事务语句分散到池中的随机连接。
- 外部调用要有明确超时、有限重试、错误记录和成本边界。付费媒体创建结果不明时先对账，不自动重发；不伪造成功、评分、价格或零值。
- 新代码保持完整类型，复用 shared-types；项目已有测试的模块按现有惯例补充回归，不为无测试项目擅自搭建脚手架。
- 配置和密钥通过现有环境/config 封装读取；禁止硬编码密钥或在输出中打印敏感值。

## 五、知识与文档闭环

1. 业务决策前先检索 RAG；故障时按现行降级规则记录，不能把未检索伪装成已检索。
2. 新知识经 `knowledgeGate + persistToPlaybook` 入库并验证检索，禁止手写 SQL 绕过门禁。
3. 每周维护覆盖项目自有 Markdown：根目录、`.claude/`、`.github/`、`docs/`、`docker/`、`packages/`、在用工具说明及 `temp/` 中仍承担现行说明的文件。
4. `temp/` 的历史调研、虚拟环境、第三方模板与安装说明不当作 SOP；清理前备份，替代证据不存在时不得删除有效知识。
5. 修改规则、架构或操作方式时，同步修正受影响的文档与交叉引用，不只更新主状态文件。

## 六、部署与验收

- 生产启动：`docker compose --profile production --env-file .env.production up -d`。
- 生产备份由 API 内建任务执行 `pg_dump → .sql.gz[.enc]`；恢复需按运维手册演练，不使用一键覆盖生产的捷径。
- 交付前运行项目标准的 `pnpm test`、`pnpm build`、`pnpm lint`，并实际验证用户场景。测试全绿不能替代真实 API/页面回读。
- 未完成、未部署或未回读的内容必须如实标记；不得把设计目标写成已上线能力。
