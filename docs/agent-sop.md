# Ozon 冷启动 · Agent 组织架构 & 流水线 SOP（终极定稿 v1.0）

> 2026-07-29 定稿。总控（主 Agent）+ 6 专家 Agent。每个 Agent「产出验收标准 + 权限边界 + 失败处理规则」——做完 ≠ 合格，必须过验收。

## 二、流水线（最终定稿）

```
选品专家 输出候选清单
  → 总控评审 GO/NO-GO（拦截：HD 干净图 <3 直接终止）
    ✅ GO → 三 Agent 安全并行【视觉设计 ∥ 俄语文案 ∥ 定价分析】
       核心：三并行全部完成且各自自检合格，才进下一环节（前置自检机制）
    ↓
  总控执行：类目匹配 + 属性填充 + API 建品 + 库存 + 富内容
    ↓
  质检专家 全量验收
    ✅ PASS → 广告冷启动
    ❌ FAIL → 精准整改工单（责任 Agent 专项整改）→ 复检（闭环）
    ↓
  广告运营 投放 + 数据复盘 → 结论同步选品专家 → 迭代下一轮
```

### 前置自检（新增）
所有专家 Agent 产出后**先自检达标**再提交总控/下游，大幅降低返工率。

### 整改 SOP（强制）
- 单次 FAIL 必须输出：问题位置、错误原因、整改标准、负责 Agent
- **最大重试 2 次**：2 次复检仍不过 → 总控判 NO-GO 终止该 SKU，避免无效消耗
- 整改记录归档，作 Agent 迭代与选品避雷数据

## 三、五条核心红线（全员强制）

1. **选品红线**：干净 HD 原图 <3 张，直接 NO-GO，禁止进入任何制作流程
2. **素材红线**：禁止裁剪/拉伸中文供应商模糊图；素材不足统一用"俄文卖点模板合成制图"
3. **质检闸门红线**：无质检 PASS 报告，禁止广告投放、禁止进流量池
4. **整改终止红线**：单 SKU 整改复检失败 ≥2 次，直接废弃
5. **数据闭环红线**：每轮广告复盘结论必须同步选品专家，实现越做越精准，禁止流水式无复盘上架

## 五、效率提升补充（2026-07-29 叠加）

### 选品前置三重筛查（选品专家必做，先行拦截）
- **资质认证**：需 EAC/3C/儿童资质的品直接 NO-GO
- **物流禁运/敏感品**：带电（内置电池）、液体、粉末、超大超重易碎——排查后决定
- **毛利率阈值**：测算毛利率 <40%（预留广告/折扣/退货）直接淘汰；同款大量低价内卷竞品避让

### Agent 产出自检（强制前置）
- 视觉/文案/定价三并行 Agent 产出后**先自检并输出自检报告**（JSON 模板），不合格内部重跑，再提交总控——压力不后移到质检
- 并行支持**局部重试**：单模块不合格只重跑该 Agent，其他成果保留

### 广告冷启动 7–14 天 SOP（广告运营执行）
- **0–7 天 数据采集期**：CPC 小额受控，不抢位；收集搜索词，CTR≥1.5% 合格（低则判素材/标题缺陷）；无效搜索词加否定词
- **7–14 天 潜力筛选**：稳定点击+加购 → 适度提预算；零互动 → 降预算暂停止损
- **0 评价新品不重仓**：先优惠券破零积累评价再加大预算；潜力款持续优化，低效款快速关停
- 复盘结论结构化回传选品专家（出单类目/卖点/价格带）

### 质检双审
- ①上架前预审（总控提交后正式发布前）②上架后线上复核（属性/图/价显示）
- 整改工单结构化：问题位置+违规类型+整改标准+责任 Agent，自动分发
- 反复问题沉淀进 `docs/pitfalls.md`（错误知识库），上游 Agent 前置规避

### 技术保障
- Agent IO 强制 JSON（禁自由文本），便于程序解析与任务流转
- BullMQ 限流控制并行 SKU 流水线数量，防 LLM 算力瞬间打满
- SQLite Checkpointer 状态持久化，任务中断可恢复
- 统一素材资源库（原图/图集/文案/定价集中存储，多 Agent 共享）
- 类目→属性模板库：同类目 SKU 通用属性自动预填充，总控减负
